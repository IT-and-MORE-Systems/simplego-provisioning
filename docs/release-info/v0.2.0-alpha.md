# Release Notes: v0.2.0-alpha

**Release Date:** November 27, 2026
**Previous Version:** v0.1.0-alpha (build 1)
**Build:** 2 (`sxprov --version`: "SimpleGo Provisioning 0.2.0 alpha (build 2)")

---

## Highlights

- **Feature profile** - activation and update files can carry the customer's feature profile (`features`, format document section 12.1): which functions are fixed on or off, per customer and device class, stored in the admin store and written into every file for that class.
- **Customer directory** - activation files can carry the device's directory entry (`directory`, section 12.2): its display name, its role and the groups it joins, with group links accepted only as short links on one of the customer's own SMP servers (section 12.4).
- **Deliveries that need the file import** - `deliver` refuses a fixed feature profile or a directory entry while the messenger cannot import the activation file, before anything is issued, and checks the profile the app reports in its final check.
- **Store key** - the admin store opens with a random 256-bit store key that nobody types: sealed with the laptop's TPM 2.0 where there is one, otherwise a key file on the encrypted disk. `store migrate` moves a passphrase store once.
- **Backups** - automatic, encrypted backups of the admin store in the SimpleGo backup format v1 (age, X25519 recipient, scrypt), after every store write and daily, to the laptop's own disk and to destinations off the laptop (USB stick or PC share, WebDAV or Nextcloud over Tor), each read back and checked; rotation, a monthly restore drill, restore, a recovery code shown once.
- **Lab files** - `activation issue --test-delivery` writes lab files signed with the TEST ONLY key, always with the published lab code `727272+727272`, without a terminal.
- **README** - the suite banner and the parts of the SimpleGo security suite.

## Changes

### Activation files

| Detail | Value |
|:-------|:------|
| `features` | `profile_version` 1, ten switches, values `on`, `off`, `ask`; fail closed inside (unknown name or value, `null`, duplicate key, array refused); a desktop-only switch `on` refused in a phone file |
| `features_profile`, `features_fixed` | SHA-256 over the canonical JSON (keys sorted, no spaces, not normalized), first 16 hex characters; the fixed switches sorted by name |
| Updates | Without `features` the installed profile stays; with `features` it is replaced; `sxprov` re-states the stored profile in every update |
| `directory` | Activation files only; `directory_version` 1, random `set_id`, `display_name`, `role` (`owner` or `member`), 1 to 20 groups |
| Names | 1 to 50 characters, valid SimpleX names (the v7.1.4 core refuses `.` and other characters); the generator writes Latin letters including accented letters and umlauts, digits, spaces and hyphens |
| Group links | Short form `https://<host>/g#<key>?...&c=...` only; the server must be one of `servers.smp`; the network mode rule of the servers |
| Strict objects | The payload and both objects must be JSON objects (serde alone also read an array of the fields) |
| Test vectors | 38 new `.sxact` vectors for both objects; every earlier vector is byte-identical |

### Admin store

| Detail | Value |
|:-------|:------|
| Container | `SXDB` version 2: AES-256-GCM under the store key, a key id in the header (a wrong key is named as such, never as damage) |
| Store key | TPM 2.0 through `systemd-creds --user` (`--with-key=tpm2`, no PCR binding) into `admin-store.sxdb.key.cred`, where `/dev/tpmrm0` exists and `systemd-creds has-tpm2` succeeds; otherwise `admin-store.sxdb.key` (0600), written only onto a dm-crypt disk outside WSL; detected at run time and named in the output |
| `store migrate` | The passphrase typed one last time; the result checked with the key read back; the passphrase file kept as `admin-store.sxdb.v1-before-store-key` until the first successful drill |
| Content | Version 4 (feature profiles and directory sets), unchanged by the store key |

### Backups

| Detail | Value |
|:-------|:------|
| Format | SimpleGo backup format v1, product `admin-store`: magic line, header with the wrapped seed, binary age file; inside a strict ustar archive with `manifest.json` (every SHA-256), `admin/store.sxdb`, `admin/store-key`, `admin/config.toml` (without machine paths) |
| Keys | Recovery code (32 characters, 8 groups, checksum) shown once; the backup key pair derived with HKDF-SHA256; the seed wrapped under the backup password with age scrypt, work factor 20; readers accept 18 to 22 |
| When | At the end of every command that wrote the store or the config; at the end of any command when the last good backup is older than 24 hours; hourly from the systemd user timer (`backup timer install`), which writes when the last good one is older than 24 hours |
| Destinations | `local` (next to the store, always on); folders with a marker (an unplugged stick is skipped, never written to); WebDAV over Tor (`https://`, or `http://` for a `.onion` host), credentials in a 0600 file of their own |
| Checks | Every file read back and checked in full with the file key kept in memory during encryption; `backup verify` re-reads every listed file; the monthly drill opens the newest files with the password or the code, restores into a temporary folder and compares |
| Rotation | The newest 30 per destination and the newest of each of the last 30 days; only files of our own list, only after the check |
| Restore | Never over the live store without `--replace` and a typed `REPLACE`; on a new laptop to the configured path, with the backups set up again |
| Warnings | Not set up, no good backup in 48 hours, no drill in 35 days, nothing off the laptop |
| Assistant | `--json` events on every command; `--code-fd` and `--confirm-fd` for the recovery code and the answers; neither the code nor a password is ever in the event stream |
| Cross-check | Files opened and written by the official `age` tool (Debian's `age` 1.2.1) in both directions, `tools/age_crosscheck.py` |

### Commands

| Command | Change |
|:--------|:-------|
| `store init` | A new store and its store key; nothing typed, no terminal needed |
| `store migrate` | New: a passphrase store to a store key |
| `store list` | Names where the store key lives; the stored profile per device class and the size of the directory set |
| `backup ...` | New: `init`, `now`, `list`, `verify`, `drill`, `restore`, `password`, `new-code`, `destination add|remove|list`, `timer install|remove` |
| `activation issue` | `--features FILE`, `--directory FILE` (needs `--serial`); prints the profile and its changes once the store is open; `--test-delivery` for lab files |
| `activation update` | `--features FILE`; `--directory` is a usage error |
| `activation inspect` | Shows both objects, the `features_profile=` and `features_fixed=` lines; the display name hidden unless `--show-names` |
| `deliver` | `--features FILE`, `--directory FILE`; stops after step 8 (and in step 12) with exit 17 when the messenger does not report `file_import=yes`, nothing issued; step 14 compares the reported profile (exit 18 on a difference); the dry run names the need |
| Exit codes | 29 (backup failed), 30 (wrong backup password or recovery code, not confirmed) |

## Upgrade Notes

- **The admin store needs `sxprov store migrate` once**: the store passphrase is asked one last time, then the store opens with its store key. Until then every other command refuses the store (exit 12). After the migration, `sxprov` 0.1.0-alpha cannot open the store any more.
- **Set up the backups** with `sxprov backup init` (the recovery code on paper, a backup password), add a destination off the laptop with `backup destination add`, and install the timer with `backup timer install`. Every command warns until this is done.
- `--test-store-passphrase-file` is gone from `deliver`, `undeliver`, `activation issue` and `flash` (a usage error now); only `store migrate --test-delivery` takes it. `store init --test-delivery` is gone: `store init` needs no terminal.
- The admin store's content version is 4 (feature profiles and directory sets). A store of version 1 to 3 is migrated when it is opened and written as version 4 on the next save.
- The admin store keeps no display name and no group link: give them again with `--directory` for each device.
- No app may report the file import capability to `sxprov` before it implements section 12 of the format document.
- The other SimpleGo products' backup readers must ignore one `*-grease` stanza beside the X25519 recipient: the Rust `age` crate adds one to every file.
